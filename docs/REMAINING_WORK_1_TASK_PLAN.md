## 1. 目的と境界

[現行・到達仕様の残り作業1](AUTOCLIPPER_CURRENT_AND_TARGET_SPEC_2026-09-25.md#remaining-1)を具体化する。範囲・タイトル・フック文言／映像・サムネ・画角・文字スタイル・軽い演出・投稿文の選択と記録を対象とする。

- 字幕の最終修正と投稿は当面人が行う。字幕確認の一回確定、手動で直す操作、再選定、戻る導線を維持する。
- 正常時に人が選ぶ項目を減らす。自動処理が失敗したときは、理由と修正手段を示す。手動設定や編集中の下書きを自動生成で上書きしない。
- 既存の生成器・描画・4つの自動化モード・キュー・制作記録を使う。新たな生成サービス、分析基盤、別の恒久台帳、汎用編集画面は作らない。
- 当面のフローは「アップロード → 自動選定／文言等の決定 → 人の字幕確認 → 確定／書き出し → 投稿用ファイルの保存」。候補不足や検証失敗では既存の確認画面へ戻す。
- §3と統合構想、残り作業1〜7の順序は変更しない。成績からの方針自動更新、完成MP4の意味検査、投稿見送り、自動投稿は後続の作業。

### 1-A：制作記録の選択履歴

**変更案**

- `production_records.py`のモデル・組み立てと契約v1を互換拡張する。旧記録に項目がなくても読むことができ、根拠のない値を補わない。既存の範囲選定・タイトル／フック案・サムネ候補・キャラ設定・描画結果から採れる値を先に記録する。
- clipごとに選択の種類、候補IDと比較に必要な値、採用／不採用、理由または理由未記録、選択元（自動／手動／プリセット／既定／代替）、入力の版、使用した選び方の版、適用時点を残す。候補が1つしかない場合は代替案を捏造しない。
- `revision`は記録の更新回数として維持し、選び方の版とは区別する。残り作業1では実装時に付ける固定の版識別子までとし、成績から版を自動生成・切替する仕組みは残り作業3に任せる。
- 作業中の履歴は既存のclip plan／字幕確認データ・生成記録に保持し、完成時に既存のproduction recordへ投影する。消えるjob出力内のファイル名だけを根拠にせず、比較に必要な最小情報を長期記録へ残す。別DBや二重の恒久台帳は作らない。
- 自動採用後に人が変更した場合は元の決定と最終値を区別する。候補や字幕の変更に伴う再生成では、古い候補を現行の根拠として扱わない。既存のrequest ID・revision hash等を再利用する。
- 現行契約は完成後のサムネ編集を即時反映しない。関連する編集の成功時にも既存の記録更新を接続する案とし、同じexportのrevision増加・createdAt維持、再書き出しのpreviousRecordId、記録失敗時に動画を失敗にしない挙動を保つ。
- 字幕全文、画像、絶対パス、秘密情報、YouTube統計を新たに制作記録へ含めない。候補ID対応が不明な既存記録はjob単位等の範囲を明示する。

**主な変更先**: `backend/app/production_records.py`、各既存サマリー／書き出しメタデータ／編集成功の呼び出し元、`docs/PRODUCTION_RECORD_CONTRACT_v1.md`、関連テスト。

**完了条件**: 旧記録の読込、候補→推薦→採用→人の変更→完成物の追跡、再書き出し／完成後編集／失敗時、job出力削除後の保持をテストする。1-B〜1-Dで追加する決定項目はこの契約へ順次接続し、1-Aだけで全項目の記録完了とはしない。

### 1-B：自動決定から人の字幕確認へ

**task-222の実装範囲**: 新規作成時の`auto`にだけ`auto-human-subtitle-review-v1`を付け、推薦適用後は人の字幕確認で止める。画面の新規既定を`auto`へ変更し、保存済みの旧ジョブには版を補わない。人の確定前は簡易プレビューだけを用意し、正式プレビュー完了後も明示的な最終書き出しを待つ。候補不足・選定失敗は切り抜き確認、文言生成失敗は字幕確認へ戻す。検証結果と実動画等の未確認事項はSTATUSのtask-222を参照。

**変更案**

- 新規の自動選定ジョブでは、既存のCodex選定、`_generate_auto_title_hook_evidence`、推薦適用、投稿文組み立てを使う。新しい選定器・文言生成器・5つ目のモードは作らない。
- **承認済みの既定値方針**: 新規の自動選定ジョブを、既存`auto`を使う「字幕確認で人を待つ」版へ切り替える。現在の新規画面の`manual`既定の変更は1-Bで実装する。手動範囲指定のワークフロー、保存済みジョブの設定・再試行は従来の経路を維持し、新しい方針版の対象を明確にする。
- 正常時は範囲・種類・本数を自動決定し、タイトル／フック／投稿文の検証済み推薦を適用して`awaiting_subtitle_review`で停止する。品質ゲートが通っただけでは字幕を確認済みにせず、書き出しへ進めない。
- 本数不足・0件・尺違反・不採用区間・根拠不備等は既存の検証と確認画面を使う。検証失敗を黙って別案へすり替えたり、弱い候補で本数を埋めたりしない。
- 字幕確認へ入る時点では簡易プレビューを用意し、確定時だけ正式プレビューを作る。自動文言適用を理由に不要な焼き込みを追加しない。
- 人が字幕を直しても文言や投稿文を毎回自動生成し直さない。根拠が古くなったときは既存の再生成・編集へ案内し、人の下書きを保護する。候補確認からの再開、retry、再編集でも二重生成／二重enqueueを避ける。
- 決定と例外・手動修正は1-Aへ記録する。`known`／`unknown`、実績ヒントなし／OFF／期限切れ、本編／フックの尺規則は変えない。

**主な変更先**: `backend/app/jobs/runner.py`、`automation.py`、`title_hook_suggestions.py`、`clip_plan_runner.py`、必要な既存API／新規ジョブ設定UI、関連テスト。

**完了条件**: 正常系で切り抜き・文言の選択操作をせず字幕確認へ到達し、そこで必ず止まる。字幕修正→一回確定→正式プレビュー→最終書き出しが成立する。手動／旧ジョブ、不足・生成失敗、戻る／再試行を検証する。

### 1-C：通常サムネの最終決定

**実装範囲（task-223）**: 1-Bの新規auto版だけで、確定字幕・公開タイトルを既存の専用文言生成器へ渡し、検証済み推薦を自動採用する。同じ確定入力は既存の提案保存先で再利用する。手動指定・旧モードを維持し、失敗時の初期文言使用は理由付きで表示・記録する。文言と画像の決定は既存choiceHistory／制作記録へ接続する。実Codex・実動画の受入は未確認で、PRは未マージのまま止める。

**変更案**

- 自動時の最終文言は、既存の専用`CodexThumbnailCopyGenerator`で生成・検証した推薦を使う（承認済み）。タイトル／フック案に同梱された文言は初期値・旧経路の互換として扱い、2つの推薦を人に選ばせる新画面は作らない。
- 専用生成の現在の入力組み立てはcompletedを前提にする。確定した字幕・公開タイトルから入力を作る共通部分を切り出して再利用し、未完成のExportItemを偽装して完成後APIを呼ばない。元の字幕の代わりに未確定の下書きを根拠にしない。
- 一つの確定入力につき専用の自動生成は1回とし、既存の不正出力時の限定再試行・人物名／根拠検証を維持する。手動で文言を指定した場合は再生成せず、その採用を記録する。
- 画像は既存のclip内候補の順位と半身構図を使い、候補0件なら予備素材、さらに無ければ従来の動画コマへ進む。既存の代替理由、拡大率の注意、素材の表情選択を保つ。新しい画像生成や全動画走査はしない。
- 画像と文言、推薦／採用ID、代替理由、テンプレ・設定を1-Aへ記録する。完成後に人が変更した場合も1-Aの更新経路を使う。専用生成が失敗した場合は理由を表示し、適用していない推薦を成功として記録しない。

**主な変更先**: `backend/app/jobs/thumbnail_copy.py`、`thumbnails.py`、既存の書き出し接続部、必要な結果画面表示、関連テスト。画像候補抽出や生成モデルを新設しない。

**完了条件**: 通常動画の最終サムネが既存の生成器と候補だけで決まり、保存画像と記録が一致する。人物名条件、素材への代替、生成失敗、手動指定、完成後編集を検証する。ショートの現行サムネ生成は不変。
