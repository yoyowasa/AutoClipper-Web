## 3. 通常サムネの原因と修正

保存されたメタデータでは、両clipの候補0件により `source=asset`。その後、人が同じ保存済み時刻の動画コマへ切り替えた。
232.38秒・39.5秒は人が変更する前の書き出し記録にも存在する。特定のジョブ・時刻をコードへ埋め込んでいない。

原因を段階ごとに検証した:

1. **検出**: ユーザー採用コマは正面検出で両方None。縮小画像を回転すると検出できた。
   サムネ候補だけに、正面で見つからないときの±10/15/20度の探索を追加。中心座標を元画像へ逆変換する。
   動画全体の走査・素材登録等の共通検出は変更しない。
2. **配置の適格性**: 旧処理は顔の高さから固定した胸元位置が元画像の下端を越えるだけで却下していた。
   実動画の旧走査では通常1が顔検出291コマ中290、通常2が277コマ中270で配置条件に落ちた。
   顔中心を上から30%に保ち、可視範囲の胸元まで切り出しを縮める。顔アップより狭くしない・拡大2倍以内という条件を維持する。
3. **候補保持**: 0.5秒格子や似た高得点12コマだけでは、文言生成側が選んだ正確な時刻を落とし得る。
   既存の提案時刻を1枚だけ追加確認し、同じ顔・画角・鮮明さの条件を通った場合に上位12件の1枠へ残す。
   時刻が範囲外、顔が不明、過度の拡大の場合は強制採用しない。候補一覧の得点順は維持する。
4. **描画への受け渡し**: 保存した顔で配置できても、背景除去時に正面検出をやり直してNoneとなる経路があった。
   候補の検出済み顔をマスク作成にも渡し、顔の座標をキャッシュキーにも含める。
5. **自動選択**: 得点の先頭は通常2で目を閉じたコマだった。既存の内容に基づく提案時刻が上の検証を通った場合は、その候補を採用する。
   適格な提案時刻がなければ従来の得点先頭へ戻す。新しいAI呼び出しを足さず、`content_proposal` / `candidate_score`、
   選択時刻・候補ID・理由を既存メタデータとchoiceHistoryへ残す。

## 4. 検証の境界・残件

- 実動画・コピーJSON57件の計58ファイルは、再計算前後のSHA-256一致を確認。稼働DBは読み取り専用からbackupしただけ。
- QA成果物は作業worktreeの `.codex_tmp/qa/` に保存。`copy-comparison.json`、`scan-results.json`、`old-extraction.json`、
  `replays/`、`thumbnail-comparison.jpg`。字幕全文・画像・DBはPRへ含めない。
- コピー環境では動画サイズをDBの1920×1080から与えた（実抽出画像も同じサイズ）。ffmpegの実走査・実画像の検出・実描画は省略していない。
- 不在だった字幕IDを古い提案入力から参照するQAスクリプトの問題を、現在の字幕確認データから入力を作る形で修正して続行した。
  製品の既存ジョブや字幕を変更したわけではない。
- 稼働中の古いキャッシュは書き換えない。今回のコードは新規抽出時に適用される。
- 最大6角度の顔探索によりCPU負荷は増える。30分clipの追加処理時間は未計測。
- 本ユーザーの完了条件である **「字幕以外を人が直さずに済む割合」そのものは未確認**。
  固定候補の一致率・採用フレームの一致・素材への代替解消は改善したが、構図と新規文言の受入をまだ代替できない。
  PRは未マージでレビューに回し、実動画全工程の受入成功とは記録しない。
