# 選び方の版と、投稿成績による自動更新（task-235、task-251で基準改定）

到達仕様の残り作業3。残り作業2の[定時分析・30日評価](INTELLIGENCE_SCHEDULING_EVALUATION.md)、
既存のintelligenceキュー、制作ヒント・改善試験、制作記録を再利用する。
新しい常駐処理・Codex依頼・有料APIは追加しない。launcherとプロンプト本文・返答の形は変更しないため、
**task-235単独ではCodex中継の再起動は不要**。別タスクの未反映分の要否とは区別する。

## 更新してよい値

[固定の許可リスト](../backend/app/intelligence/choice_policy_schema.py)にある数値だけを保存・適用する。
既定はすべて1.0、絶対範囲は0.5〜2.0。任意のキー、文字列の指示、パス、コード、新しい方式は受け付けない。

| 対象 | 実際に変えるもの | 維持するもの |
|---|---|---|
| 候補順位 | 低知名度ショートの既存冒頭評価への倍率 | knownの順位、元の品質点・採用条件、通常の順位 |
| タイトル・フック | 検証済み3案の既存intent（factual / engagement / concise）の優先度 | プロンプト、字幕根拠・題材語等の検証、元の推薦ID |
| 画角 | 既存の5方式の優先度 | 人の指定、内容判断の根拠、実際の幾何検査・安全な代替処理 |
| 文字スタイル | title / hook / subtitleの既存bold / regularの優先度 | ユーザーのフォント・色・サイズ上限・収まり処理・手動指定 |
| 軽い演出 | 既存の行ごとの強調の題材・数・反応点への倍率 | 強調数・間隔・安全条件、動的演出を追加しない |
| 通常／ショート配分 | 既存AI配分での形式別順位への倍率 | 合計・最低本数、手動・キープ、尺・強い候補の条件、旧fixedの互換 |

新しい選択肢を探索生成する機能ではない。実際に観測した既存の選択肢同士の比較から、
1項目だけに対応できる場合に限り更新する。複数の違いが混ざる比較は採用しない。
冒頭点の帯、実際の本数配分、選んだ強調の種類、使った倍率も許可した比較値として記録する。
冒頭点は完成区間と一致する選定記録から受け継ぎ、低知名度設定が記録された比較だけを順位更新に使う。
書き出し時の強調が適用時の値と一致するときは、その判断・倍率を完成時の履歴にも保持する。
手動／fallbackの画角も、実際の描画指定と一致する適用履歴がある場合だけ出所を受け継ぐ。
生成結果そのものや字幕本文を設定値に変換しない。

## 承認された更新・保留・巻き戻し基準

以下の20%・10%・本数は、ユーザーが承認した**未検証の運用基準**（2026-10-29承認、2026-11-12改定）。
因果効果を確認した基準でも最適な重みでもない。task-234のeffect=unconfirmedを維持する。

**2026-11-12改定（task-251、ユーザー承認）。** 学習を早く回すため、待ち時間と分け方の条件を減らした。
1回1項目・最大10%・悪化時の自動巻き戻し・許可リスト・欠損を0にしない点は変えていない。

| 項目 | 改定前 | 現在 |
|---|---|---|
| 使う成績 | 30日だけ | 7日で仮判定、30日で確定 |
| 必要本数（比較する両群） | 5本 | 仮判定3本、確定5本 |
| 群の分け方 | 尺帯・実装版・使用方針版・出所でも分ける | キャラ・形式・項目・記録された値だけ |
| 出所未記録の記録 | 使わない | 記録に残っている値は使う。無い値は推定しない |
| 到達率が下がらないこと | 必須 | 条件から外した（現状は全群0%で判定に効かないため） |
| 更新後の版の判定 | 30日5本まで次の更新を保留、7日は警告だけ | 7日3本で判定。悪化なら巻き戻し、悪化なしなら次の更新を探す |

1. 同じチャンネル・キャラ・形式で、同じ項目の値が違う、重複しない動画群を比較する。
   群は記録された値で分ける。尺帯・実装版・使用方針版・出所（自動／手動／fallback／未記録）では分けない。
   出所は群の属性として保存・表示する（複数が混ざる群は`mixed`）。
   手で直した項目の値はその項目の観測として数え、直していない項目は自動の観測として数える。
   選択履歴の無い旧記録は、記録に残る「投稿されたタイトル候補のintent」だけを観測として使う
   （選択候補の題名が投稿題名と一致し、intentが許可値のときに限る。出所は未記録のまま）。
   記録に無い値（旧記録の低知名度設定、編集後の題名のintentなど）は推定しない。
2. 両群の30日判定済みが5本以上なら**確定**、それに満たず7日の成績が両群3本以上なら**仮判定**として比較する。
   再生数の中央値が20%以上良い値があれば、その1項目を最大10%変更する。
   候補が複数あるときは確定を優先し、次に改善率の大きいものを選ぶ。
   同じ分析の完了につきチャンネル全体で更新は1項目まで。手動の採用操作は不要。
   仮判定の更新は`PROVISIONAL_7_DAY_CRITERIA_MET`、確定の更新は`OBSERVATIONAL_CRITERIA_MET`として記録する。
3. 更新後の版は、その版IDが記録された動画と、同じキャラ・形式のそれ以外の動画を比較して判定する。
   30日が両群5本以上ならそれを、無ければ7日が両群3本以上ならそれを使う。
   中央値が20%以上悪化していれば直前版へ自動で戻す（`REGRESSION_30_DAY` / `REGRESSION_7_DAY`）。
   本数が足りない間は次の更新を保留する（`VERSION_RESULT_PENDING`）。悪化が無ければ次の更新候補を探す。
   版IDが記録されるのは、版を固定して開始したautoジョブの動画だけ。
4. データ不足、改善20%未満、許可値に対応しない差は保留する。
   手動・自動で戻した設定の組み合わせは再採用しない。同じ根拠だけでの再更新も防ぐ。
   新版に戻すために足りない根拠を推定しない。
5. 人の修正そのものも学習に使う（2026-11-06にユーザーが承認）。自動の値から人が変えた値への変更（項目・変更前・変更後）を記録し、
   許可リストの選択肢に対応する修正は、成績を待たずにその選択肢の優先度へ反映する。
   同じ方向の修正が、同じチャンネル・キャラ・形式で直近5本以上そろったときだけ、1項目を最大10%動かす（重みは0.5〜2.0）。
   反映後の版も3.の判定・巻き戻しの対象にする。
   許可リストに対応しない修正（自由記述のタイトルや字幕の文字など）は記録だけにとどめ、設定値には変換しない。

旧基準で記録済みの履歴（`VERSION_30_DAY_PENDING`、`EVIDENCE_EXPIRED`、`EARLY_7_DAY_DECLINE`、`MIXED_PROVENANCE`）は
そのまま表示するが、新しくは記録しない。

比較の基準（7日／30日）・両群の本数と中央値・グループID・根拠ID・動画ID・観測時点・比較元の版を保存する。
関連する検証済み制作ヒントの集計IDと既存改善試験のIDも残すが、人の提案採用を前提にしない。
更新判定の例外は分析の成功を取り消さず、版を保持してEVALUATION_FAILEDを記録する。

## 版の保存・ジョブへの適用

- 既存DBのcreate_allでchoice_policy_heads、choice_policy_versions、choice_policy_decisionsを作る。
  設定の版は追記のみで、更新は新しい版を作る。現在の版を示すポインタだけを切り替える。
  分析ID単位の一意制約とSQLiteのチャンネル書き込みロックで二重更新を防ぐ。
- 対象は実装後に作った新規autoジョブ。処理開始時に有効な版をsettings_jsonの内部領域へ複製し、
  再試行も同じ版を使う。処理中のジョブや既存ジョブ・手動ワークフローへ遡って適用しない。
- 既存の投稿先チャンネル名channelNameとキャラ名を使い、接続済みのチャンネルを照合する。
  チャンネル名が空でも対象が1つなら適用し、複数候補や不一致は推測せず理由を内部設定に記録して既存動作を保つ。
  既存の「実績ヒントを使う」がOFFの場合も版を適用しない。新しいキャラ設定を増やさない。
- 制御対象の自動・fallback選択はchoiceHistory.policyVersionに使用した版IDを保存し、
  元の処理版は任意項目implementationVersionへ残す。手動のsource・版は保持する。
  過去の判断にすでに別の設定版IDがある場合は、現在の版に付け直さない。
  手動と自動が混在したことを隠さず、項目ごとの出所として記録し、評価に使う。
- 制作記録のschemaVersion=1を維持し、旧記録は追加項目なしで読み込める。
  ジョブを消しても永久記録から使用版を追える。公開後の履歴を投稿当時の自動判断とみなさない。

[ジョブ開始時の適用](../backend/app/intelligence/choice_policy_runtime.py)、
[制作記録契約](PRODUCTION_RECORD_CONTRACT_v1.md)を参照。

## 履歴・画面・保持

分析画面の「選び方の版」に現在の版、更新・保留・巻き戻しの全履歴、比較の根拠（仮判定／確定の別を含む）を表示する。
現在の版に直前版がある場合は、確認を経て「直前の版に戻す」ことができる。
画面を開いてから版が変わっていた場合は409で拒否する。既存ジョブの複製済みの版は変更しない。

- GET /api/intelligence/channels/{channel_id}/choice-policies
- POST /api/intelligence/channels/{channel_id}/choice-policies/{policy_id}/rollback
  （expectedVersionを必須とし、既存のOrigin確認を適用）

比較根拠は元の独自集計の最短期限（最大36か月、拡張保存無効時は30日）を超えない。
期限後は根拠を消し、値を表示・更新に再利用しない。自前の設定版、変更・保留理由、関連版IDは残す。
YouTubeタイトル・統計本文を設定版やログへ複製しない。
