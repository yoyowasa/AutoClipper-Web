# 完成MP4の独立検査・局所修復 v1（task-236）

## 対象と完成の条件

書き出しとサムネ生成の後、completedへの遷移・再書き出しの公開前に、RQの既存レンダリング工程から検査を呼ぶ。
検査器は描画器とは別の `app/inspection/`。生成したMP4をffprobeとFFmpegで開いて観測する。
HTTPでは動画解析もCodex待ちも行わない。既存の選定・内容・post_render品質ゲートと画角の自動修復は維持する。
対象clip全件の検査がpassになるまで新しい成果物を完成として公開しない。unknownも未完成として停止する。
完成済みジョブへの一括再検査や遡及的な未完成化は行わない。選択的な再書き出しはrenderClipIdsだけを検査する。

流用: `_render_selected_outputs`、renderClipIds、字幕確認の確定値とASS生成、タイトル／フックとサムネ文言の既存生成器、
既存Codex中継、品質ゲート、再書き出しのstaging・公開・巻き戻し、制作記録、既存の人による編集／再確定。
新規: 実ファイルの検査器、clip単位の上限付き修復制御、検査JSON、内容整合用の中継依頼、未完成理由の表示。
新しいキュー・常駐プロセス・有料API・DBテーブルは追加しない。

## 観測するものと閾値

| 項目 | 観測・判定 |
| --- | --- |
| 読み取り・ストリーム | 実MP4のffprobe。映像・音声必須。ストリーム長が読めない場合も合格にしない |
| 尺 | 確定した本編＋別枠フックとの誤差0.5秒以内。映像／音声の長さの差も0.5秒以内 |
| 解像度 | shortは1080×1920、normalは元映像の登録サイズ。既存の出力契約検査も継続 |
| 黒・無音・静止 | 全区間を順次デコード。黒は画素閾値0.10・面積98%・3秒以上、無音は-50dB・3秒以上、静止は-50dB・10秒以上 |
| 元動画との比較 | フック／本編それぞれの元区間も同じ検出を行う。元に存在する静止・無音・黒は記録し、書き出しで増えた区間だけ不備とする（境界誤差0.5秒）。元比較不能はunknown |
| 字幕 | 確定したclip固有字幕・スタイルから新たに作ったASSを透明面に描画し、実MP4の画素と比較。出力側ASSや「描画済み」メタデータだけを証拠にしない |
| 字幕のサンプル | 5fps、幅最大480px、RGBAの不透明画素を色群別に比較（RGB差60以内、各群一致率72%以上）。文字・縁の両色で照合。各cueがサンプルに無ければunknown |
| 字幕の配置 | 参照の文字マスクが画面端2px・上下帯へ衝突、異なる字幕の表示時刻が重複、終了後0.25秒超の残留を検出 |
| 冒頭・フック | フックと本編冒頭の各最大3秒を実MP4／該当元音声で8kHzにして照合。相関0.90以上。両方無音の場合は無音検出の結果と併記 |
| 文言・サムネ | 確定字幕、公開／画面タイトル、フック、投稿文、実サムネ、完成MP4と対応する元区間の代表4コマをCodexへ渡し、内容矛盾とサムネ矛盾を別々に判定 |

上記の数値はエンコードや境界の揺れを許容する実装上の基準。実動画での精度・速度は受入未確認。
FFmpegはフレームを順次読み、全動画の画像をメモリに溜めない。外部プロセスには時間上限を設ける。
字幕を焼かない設定／対象cueがない場合はその条件を明記する。人が確定した字幕本文は変更しない。

## 内容整合の中継契約

- 依頼種別 `final_output_review`、プロンプト版 `final-output-content-v1`。通常レーンを使用する。
- 返答は `findings` 2件。kindはcontent / thumbnailを各1件、outcomeはpass / fail / unknown、reasonはsupported / contradicts / insufficient_evidence。
- 各項目は入力にある字幕IDと画像IDを引用する。字幕なしの場合は画像IDを2件以上引用する。架空ID・重複kind・結果と理由の不一致は拒否する。
- 実行上限120秒、クライアント待ち135秒。エラー・時間切れ・検証不能はunknownとして停止し、別のAPIへ切り替えない。
- 元／完成の一覧画像2枚と実サムネ1枚を使う。字幕本文は中継入力のみ。検査記録には理由コード・根拠ID・ハッシュを残し、Codexの自由文や例外本文をログへ出さない。
- payload上限18万文字。切って根拠を失うのではなく、上限超はevidence_too_largeとして停止する。
- launcherの許可種別・固定スキーマ指紋に追加する。既存種別のプロンプト・指紋・モデル・待ち時間・分析レーンは変更しない。
- **反映時はホスト側のCodex中継の再起動が必要**。このタスクでは稼働反映／再起動を行わない。

## 決まった局所修復

1clipにつき最大2回。行った修復は同じレンダリングrevisionでのworker再試行でも数え直さず、同じ修復を繰り返さない。
確定字幕・手動値・確定時のプレビュー／自動決定revisionが変わった場合は新しい入力として扱い、人の修正後の再検査を妨げない。
毎回必ず完成MP4を検査し直し、既存の品質ゲートにも再度通す。修復不能なら上限前でも止める。

| 不備 | 許可する修復 |
| --- | --- |
| 破損・尺・ストリーム・映像／音声・字幕画素・冒頭不一致 | 確定値を変えず、そのclipだけ既存経路で再書き出し1回 |
| 字幕の画面外／帯との衝突 | 自動決定済みかつ手動指定がない字幕スタイル・既存の行別強調だけ収まりを再計算。本文・時刻・他の役割・手動画角は維持 |
| 内容／サムネ矛盾 | 自動決定済みで関連する手動指定がない場合だけ、既存の検証付き文言生成器で再生成し、そのclipを再書き出し。推薦は既存方針・ヒントを使用 |
| 根拠不足・中継失敗・unknown・確定字幕同士の重複 | 自動で確定値を推測せず停止。既存の字幕／詳細編集で修正できる |

既存の画角修復（task-230、最大1回）は別の検査段階のまま。この2回に置き換えて検査を省略しない。
手動値はmanualDecisionFieldsで保護する。字幕全件と保護値を前後照合し、修復で変われば復元して停止する。
修復・再検査は未公開の成果物だけを置き換える。再書き出しが落ちた場合の元のMP4・ExportItem・制作記録の保全は既存の巻き戻しに従う。

RQの追加予算は対象clipの尺・件数から、初回＋最大2回の検査（元／完成デコード・字幕の2系統）、最大2回の局所レンダリング、
3回分の内容判定、1回の既存文言再生成の上限待ちを積算する。新規選定前は要求本数×最長1800秒から保守的に見積もる。
これは上限予算で、30分clipや複数clipの実測完了時間を保証する値ではない。

## 記録・停止・再編集

`StoragePaths.final_output_inspection(job_id, clip_id)`:
`storage/outputs/<job_id>/final_inspection/<clip_id>.json`。write_json_atomicで書く。
version / job_id / clip_id / label（通常1等）/ input_revision / created_at / updated_at / max_repairs / outcome / attemptsを持つ。
attemptsはindex / output_sha256 / checks（code, outcome, evidence, second）/ repair / repair_result。
修復を予定した時点でも保存するので、worker強制終了を無記録の再試行にしない。秒は完成clip内。

検査に落ちるとerror_code=final_output_incomplete。字幕確認または手動範囲編集に戻し、対象の表示名・理由・時刻を出す。
字幕確認のautomatic_stop_reasonsと、Job詳細のfinalInspectionを使う。内部候補IDを失敗理由の画面表示にしない。
既存の確認画面で修正・再確定できる。検査記録の保存失敗も完成扱いにせずfinal_output_record_failedで停止する。

検査JSONはジョブの出力と同じ寿命。合格した成果物には制作記録の任意項目finalInspectionとして、パスや字幕本文を含まない証拠を複製する。
MP4のSHA256と、サムネ・公開タイトル／投稿文／サムネ文言のハッシュが検査時と一致する場合だけ複製する。
結果画面で別のサムネ等へ変えた場合、古い内容整合の合格を新しい値の証拠として転記しない。完成済み状態を遡って変更することもしない。

## 検証の範囲と残る受入

テストでは実際に短いMP4を作り、正常・尺違い・音声欠落・AVずれ・解像度違い・黒・静止・無音・冒頭違い・
字幕の欠落／文字違い／時刻ずれ／はみ出し／重なり／帯衝突を確認する。修復制御は偽エンコーダ・偽Codexで局所再実行、
再検査、上限停止、手動値保護、完成判定、公開失敗の巻き戻しを検証する。実Codexは呼ばない。

Windowsのローカル媒体テストは既存FFmpegを使い、ffprobeがない場合だけテスト内でPyAVによる実ファイル読み取りを代用する。
Linux CIは本番と同じffprobeを使う。スキップされた条件を実施済みとしない。

**実際の完成動画での受入は未確認**。代表画像での意味判定は全フレーム／全音声の理解ではなく、字幕照合はOCRや発話の正誤判定ではない。
5fps未満の短いcue・日本語フォント・複雑な演出・実動画の静止／BGM・GPUエンコード・検査時間・Codex誤判定の受入を別途行う。
この未確認範囲を、全面的な映像・音声理解や字幕の意味修正を達成したという記述に置き換えない。
